# Lifecycle requirements audit

The governing goal is stock Zephyr 4.4.x developer experience, with understandable
remote/transport differences. This is a proposal, not a normative SRS amendment.
Baseline: corrected main `ce12b6a`; parent experiment `b74f093`. Read the actual
4.4.0 OpenOCD runner and core client/server wrappers in the supported checkout.
Flash checks a one-shot process result; debug/attach use local GDB and finally
terminate/wait for the server; debugserver is foreground; RTT has setup and client
phases. Parent SIGINT is ignored during interactive GDB. These are functional
references, not a requirement to copy their incidental subprocess algorithms.

Classification abbreviations: **P** product invariant, **S** safety invariant,
**R** remote necessity, **C** policy choice, **A** architecture leakage,
**O** overconstraint. Rows split meaningful clauses rather than assigning one
label to an entire mixed requirement. CONFIG/FLASH/DEBUG/SVC/SSH/HELP/DATA
IDs abbreviate the canonical `REQ-FUNC-` prefix. Replacement wording is
proposed only here.

| ID/clause | Current requirement | Class | Reason | Action / proposed wording |
| --- | --- | --- | --- | --- |
| §2.8, SSH-001 | Configured SSH command carries stdin/stdout/stderr and status | P/R | Session custody requires directional termination, not merely stdin input | Strengthen: a compatible helper transport shall turn local stdin closure into remote stdin EOF while retaining stdout/stderr until remote command exit. |
| §2.10 | One session lifetime lists remote and local resources | R/A | Related operation, several independent ownership/failure domains | Revise: each side owns its acquired resources; local forwarding, RTT and remote child scopes have independent cleanup authorities. No global resource coordinator is implied. |
| §2.11 | Control channel carries commands, output, startup/final result | R/A | A duplex connection is necessary; a continuing command stream is not | Revise: negotiate and start a session, retain controller input lifetime, receive diagnostics/readiness/outcome. Wire grammar belongs in protocol. |
| §3.5 | Finite project-controlled cleanup deadlines; detection/OS latency excluded | S/R/C | An unresponsive transport cannot make local shutdown wait forever | Retain bounded effort and explicit limits. Clarify that timeout proves unsuccessful waiting, not producer quiescence or remote disposal. Deadline values/algorithm belong in SAD. |
| CONFIG-020/021 | Literal effective argv; guarantees only for generated startup order | P/S | Transparent stock command semantics; opaque fixed Tcl can have side effects | Retain. Retry classifiers must establish safe repetition of generated startup, not assume arbitrary Tcl is idempotent. |
| CONFIG-022 | Verbose full effective argv | P | Stock command diagnostics are useful during failure | Retain; no redaction claim for configured literal secrets. |
| CONFIG-023 diagnostic | Exact argv before every failed/successful/retried attempt | P/C | Pre-invocation diagnostics match stock experience | Retain as diagnostic admission immediately before attempt entry; network receipt before spawn is impossible to guarantee without a new ACK. |
| CONFIG-023 wire reference | Wire-event/framing details in protocol | A | PROCESS_STARTING need not be a lifecycle transition | Move concrete ATTEMPT payload/framing to experimental protocol; keep only diagnostic obligation in SRS. |
| FLASH-005 | Failed OpenOCD flash fails west | P/S | A transport/helper result must not masquerade as a successful flash | Retain genuine one-shot child result and independently classify infrastructure failure. |
| DEBUG-001/002/005/007 | Local GDB, remote OpenOCD; stock debug/attach behavior | P/R | Symbols and debugger remain local; attach must not load | Retain. Slice tests session shape, not real target/GDB initialization. |
| DEBUG-003 launch | Startup completion and required transport precede dependent launch | P/S/R | Launching against unusable infrastructure is a real error | Strengthen: at launch entry the local operation must still be opening with readiness and required forwarding established and no established fatal failure/cancellation. |
| DEBUG-003 deadline | Finite readiness deadline starts determination; observations may finish | P/R/C | Boundary evidence should not be accidentally hidden by coroutine scheduling | Revise: determination shall account retained complete evidence and perform a bounded final observation of owned startup sources; then choose readiness or failure. Specify the finite observation cut/budget in SAD. Do not promise continued process liveness. |
| DEBUG-003 exited child | Exit before readiness fails without dependent launch | P/S | A completed server is unusable; successful one-shot flash is different | Retain for live-server policy only. Exit-policy operations require no READY. |
| DEBUG-006 | Debugserver exposes service without starting GDB | P | Foreground-server operation differs from debug | Retain. Readiness authorizes endpoint usability, not a local GDB process. |
| SVC-001 requirements | Required vs best-effort forwards, RTT phase change | P/R/C | Required paths fail operation; optional paths may warn | Retain required-path semantics and independent rollback. Classification policy is deliberate; do not merge these owners into helper lifecycle. |
| SVC-003/004/005 | Loopback allocation, exact requested local ports | S/R/P | Isolation and stable debugger addresses | Retain. Address retry is remote allocation machinery, not an exposed operation state. |
| SSH-003/004/005/006/009 | Configured argv, no shell insertion, normal credentials | P/S | Transport implementation remains selected by user | Retain. Unsupported patterns include stdin suppression, closing both directions on EOF, mandatory PTY, and helper detachment/reparenting that breaks controller custody. No STOP fallback, probe/negotiation or new YAML key. |
| SSH-010 observation | Local SSH loss records failure; remote observation is separate | P/S/R | No distributed instantaneous detection guarantee | Retain; local known failure revokes new launch, and bounded local closure does not certify remote cleanup. |
| SSH-010/HELP-011 checks | Interactive client failure handled after client returns | P/C | Preserve stock GDB Ctrl-C and interactive behavior | Retain minimum guarantee; responsive supervision may improve visibility without treating GDB Ctrl-C as cancellation. |
| SSH-011 | No transparent debugging reconstruction after loss | P/C | Reconnection cannot restore target/debugger state safely | Retain. No automatic session reconstruction in this experiment. |
| SSH-012 | Sharing externally owned; helper address authority | S/R/P | Per-channel EOF must not close user's sharing master | Retain; qualify compatible transport by directional EOF contract, not executable basename. |
| HELP-002/003/004 stdlib | Matching deployable unprivileged helper, Python stdlib | R/P | No daemon or extra host administration | Retain. Prototype is multi-file experimental code, not yet a deployable standalone artifact. |
| HELP-004/009 provenance | Helper/orderly/natural results distinct; no fabricated child status | S/P/R | Flash/debug outcomes must be honest | Retain genuine observed result independently of trigger/primary; helper and SSH statuses remain infrastructure results. |
| HELP-005 observation | Observe controller input during pending startup | S/R | EOF must trigger cleanup even if no marker arrives | Retain concurrent EOF observation with authority-linearized termination. No recognized-but-unhandled EOF success precedence. |
| HELP-005 cleanup/detection | Bounded cleanup after remote observation; detection latency unbounded | S/R | Remote process cleanup cannot start before knowledge arrives | Retain conditional progress/unsuccessful-cleanup diagnostics. EOF observed by adapter and authority handling may differ; do not claim an instantaneous network boundary. |
| HELP-006 readiness | Readiness only after configured conditions | P/S/R | A real usability boundary is necessary remotely | Retain. Remote READY after local cancellation is benign and ignored locally. |
| HELP-006 output | Incremental newline-free relay, per-stream order | P/R/S | Console/progress visibility and bounded memory | Retain per-stream FIFO and bounded storage; do not add cross-stream order. Encoding/chunking are architecture choices. |
| HELP-006 closure | Distinguishable failure/closure; final delivery may fail | P/S/R | Single structured result represents outcomes directly | Revise: commit at most one immutable terminal snapshot with trigger, genuine child result, primary and secondary diagnostics; local delivery failure adds diagnostics and cannot create another terminal snapshot. |
| HELP-006/008 Protocol v1 | Concrete v1 grammar/transition rules delegated to protocol | A/O | Internal wire contract does not define product cancellation semantics | Remove v1-specific constraint from proposed product wording; retain independent boundary validation. Wire schema belongs in protocol. |
| HELP-007 | Atomic helper revision publication and active revision protection | S/R | Lease shutdown must not remove code selected by active deployment; session and deployment ownership are separate | Retain. Deployment/revision reclamation is outside this runtime slice and should reuse current protection. |
| HELP-008 | Validate selected services before process startup | S/P | Unsupported service requests should fail before target work | Retain; does not imply inspection of arbitrary Tcl. Full service decoder is outside this slice. |
| HELP-010 one attempt | One bounded cleanup sequence; repeated shutdown harmless | S/C | Independent cleanup is necessary, exact attempt count is not | Revise: shutdown is idempotent and attempts every independently owned cleanup action under bounded policy. A deadline/error cannot abandon another resource. Retry only after proven settlement. |
| HELP-010 sharing ownership | Only launched SSH processes/pipes/drains owned locally | S/R | Do not destroy user's external sharing state | Retain. Local timeout terminates/kills only owned transport, reports uncertainty about remote cleanup. |
| HELP-010/011 transport outcome | Coordinated cleanup observes remote result and separately handles helper/SSH failure | S/R/P | A final operation failure can coexist with completed disposal; absence of a final result cannot establish remote success | Strengthen: final-result accounting shall distinguish operation outcome, disposal confirmation and local transport status; local wait expiry shall report unconfirmed remote cleanup, not success. |
| HELP-011 primary | Established operation failure preserved; secondary failures retained | S/P | Cleanup cannot hide why operation failed | Retain structured primary and ordered nested secondary diagnostics. No total order between unrelated unestablished failures. |
| HELP-011 cleanup fatal | Acquired-resource cleanup failures fail operation | S/P/C | Failed disposal is externally significant, even for optional resource | Retain fatal diagnostic, distinct from OpenOCD status. Failed cleanup leaves explicit residual responsibility rather than fictional success. |
| HELP-012 group ownership | Child, descendants and relays cleaned/reaped | S/R | A dead leader can leave live descendants or pipe writers | Retain physical ownership; signal/reap order and OS progress assumptions belong in SAD. Leader exit is not resource settlement. |
| HELP-013 signals | Flash/RTT/debugserver interruption cancels; GDB Ctrl-C remains GDB interaction | P/S | Native signal capture and local operation cancellation are different | Retain. Signal adapter latches safely; authority chooses termination; acquisition/handoff require separate interruption-safe ownership. |
| FILE-001 / DATA-003 resource lifetime | Staged files required by OpenOCD remain available; cleanup excludes active staging | P/S/R | Shutdown code or a producing operation can still use staged inputs after termination commits | Strengthen: close staging admission at workspace cleanup initiation, retain dependent inputs until child disposal is confirmed, then perform exclusive removal. Unconfirmed disposal retains the workspace and records failure. |
| DATA-003 staging | Existing stage finishes before removal; reject new stage after cleanup starts | S/R | EOF must not invalidate another legitimate workspace user | Retain separate process-shared staging lease and closed admission; bound unsuccessful waits and preserve other cleanup progress. |
| DATA-005 reclamation | Only demonstrably inactive workspaces reclaimed, opportunistic failures tolerated | S/R/C | Do not delete another developer's active work | Retain; not modeled as another helper lifecycle phase or global reservation service. |
| Protocol-only recognized STOP/EOF precedence | Recognized fact defeats READY/retry before authority handling | A/O | Local cancellation gate prevents new dependent work; later remote observation cleans all owned work | Remove from proposed contract. READY/retry may win until authority termination; retain fair, bulk-independent critical admission. Current SRS does not itself explicitly require this precedence. |
| HELP-009 / protocol closure race | Either natural or requested closure may follow local shutdown initiation | P/C | Protocol v1 already explicitly permits either result; no deterministic-winner requirement was found | Retain permitted race; keep genuine observed result independently of initiating cause. Adding winner synchronization would be an overconstraint, not a current SRS obligation. |
| Retry safety (proposed explicit rule) | Current allocation retry protected by implementation conventions | S/R | New generation cannot overlap unresolved producers/unsafe reuse | Strengthen product-level wording: retry only a classified safely repeatable startup failure, after prior producers/resources settle, and before authority termination; stale results cannot change current ownership/readiness. |

This audit does not remove actual safety duties simply because the prototype
does not implement all production behavior. File staging security, service
validation, address allocation, retained forwarding, target command construction
and real RTT/GDB operation remain product scope. The required SSH strengthening
is an internal transport compatibility contract, not a YAML schema change.
