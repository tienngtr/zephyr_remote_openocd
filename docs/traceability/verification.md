# Verification Traceability

This matrix maps SRS requirements to maintained verification evidence, including
automated tests, hardware tests, documentation, and design review. A row may
list several requirements, and a requirement may occur in several rows; this
is intentional many-to-many traceability. Coverage statuses describe maintained
evidence, not the results of any particular run.

Every SRS requirement is listed in either the implementation coverage matrix or
[controller-lease lifecycle](#controller-lease-lifecycle) matrix. Production
implements Protocol v1. The matrices identify maintained evidence at the actual
production boundaries; [integration qualification](#integration-qualification)
describes the external qualification boundaries.
Passing a pure lifecycle test alone does not qualify its physical integration.
**Documented** records user documentation, **Failing** a maintained test failing
in this environment, and **Unverified** a lack of maintained evidence.
**Reviewed** records design review with partial automated support identified;
it does not mean the full requirement has automated verification.

Status is classified by maintained coverage: **Automated** means unit,
local-process, Zephyr, or SSH integration coverage; **Hardware** means a maintained
real-hardware test requiring a configured hardware test environment; **Both**
has both forms. Availability of a configured hardware environment does not
imply that the hardware test has been executed.

Hardware evidence also depends on the harness using the selected execution
environment. [`test_hardware_launch_uses_selected_environment`](../../tests/unit/test_hardware_environment.py)
captures actual operation launches across flash, debug, RTT, and semihosting;
[`test_preparation_uses_only_configured_build_environment`](../../tests/unit/test_hardware_support.py)
protects build preparation, and the [simultaneous GDB/RTT regression](../../tests/unit/test_hardware_rtt.py)
checks both the west and independent GDB launch environments.
[`test_hardware_cleanup_stops_descendant_after_leader_exit`](../../tests/unit/test_hardware_process.py)
protects hardware abort and timeout cleanup with real descendants retaining
stdout; [`test_process_scope_preserves_failure_and_finishes_cleanup`](../../tests/unit/test_hardware_process.py)
checks cleanup completion and failure precedence when group signaling fails.
[`test_process_acquisition_interrupt_reaps_created_group`](../../tests/unit/test_hardware_process.py)
injects real SIGINT after launch and verifies rollback before publication,
including graceful child SIGINT delivery and caller handler restoration.

External acceptance also depends on test-resource cleanup.
[`test_cleanup_scopes_attempt_all_owners_and_preserve_primary`](../../tests/unit/test_harness_cleanup.py)
exercises acquisition failure, independent cleanup failures, interruption, and
primary assertion preservation through the shared test cleanup context.
[Local harness cleanup regressions](../../tests/local_integration/test_harness_cleanup.py)
exercise real managed subprocesses, independent pipe cleanup after diagnostic
drain or input-close failure, finite escalation waits, and primary failure
preservation. SSH and hardware callers consume these shared cleanup helpers.

### Differential acceptance decisions

This table classifies behavior to guide evaluation of future changes. Required
equivalence refers to supported stock Zephyr command/client behavior; benign
nondeterminism describes permitted lifecycle orderings. Qualification limits
above still apply to combined histories and external environments.

| Behavior | Classification | Contract decision / acceptance boundary |
| --- | --- | --- |
| Flash, debug, attach, debugserver, RTT, semihosting | Required equivalence | Preserve stock command/client behavior, supported options, structured RTT, and stdout/stderr console relay. |
| Late remote READY after local cancellation | Benign nondeterminism | Permit remote READY until remote termination commits; local cancellation prevents actual dependent launch. |
| Post-spawn startup failure | Required command behavior | The deployed helper does not restart a spawned child: bind failure can follow user Tcl and target effects whose repetition is not established as safe. |
| Natural child exit versus controller termination | Benign nondeterminism | Either initiating cause is valid; preserve genuine observed child status independently of that cause. |
| Native termination signal delivered to helper | Required failure behavior | Signal is helper/session failure under both policies, including during EOF-initiated cleanup. Confirmed disposal or zero child/helper/SSH status cannot mask a valid signal failure; a signal accounted after snapshot freeze remains failure through helper status. Ordinary child-disposal signals and interactive GDB Ctrl-C keep their existing meanings. |
| Explicit live-server versus one-shot completion | Required command behavior | Operation-selected START policy makes live-server READY mandatory and forbids READY/readiness timeout for process-exit sessions; one-shot exit supplies the genuine process result. |
| Startup deadline boundary evidence | Required equivalence with explicit local policy | Finite final stream/decoder/EOF/exit observation bounds readiness evidence; accept evidence within the defined cut, with live-child validation. |
| Controller-input EOF | Required transport behavior | Requires ordered input and directional EOF, retains reverse output, and scopes sharing shutdown to the controller channel. RELEASE then EOF is orderly; EOF the helper recognizes without RELEASE is lease loss whenever its terminal is received. Unread EOF at freeze is not classified. Incompatible wrappers require reconfiguration, not fallback or YAML changes. |
| Structured terminal outcome | Required result semantics | One immutable snapshot distinguishes trigger, primary, nested diagnostics, genuine result, and disposal; failed delivery never commits another. |
| Controller/transport loss and missing result | Unavoidable remote difference | Local and remote observations are separate; missing final result is infrastructure uncertainty. No instantaneous cancellation, guaranteed terminal delivery, or transparent debugger recovery. |
| Staging/child workspace dependency and residual cleanup | Required safety | Timeout is not disposal. Retain inputs for unconfirmed users; later reclamation needs positive inactivity evidence. |
| Address leases, configured argv/environment, paths, helper revision protection, forwards and RTT | Required equivalence | Keep continuous physical ownership and validation boundaries within each independent failure domain. |

A behavior contradicting a required equivalence or safety row is a regression.
New differences require classification and review before acceptance. External
qualification follows the configured testing layers,
collects nodes first, runs destructive profiles serially, and inspects cleanup
before target reuse. Pure semantic tests and static checks complement physical
production-boundary tests; they do not establish SSH or hardware qualification.
